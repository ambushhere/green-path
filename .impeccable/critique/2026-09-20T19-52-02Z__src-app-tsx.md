## Design Specificity Verdict

**Call: category-interchangeable.**

The *information model* is authored: three named tradeoffs (Direct / Green / Scenic), each with a one-line rationale, PM2.5 promoted to a first-class metric beside distance and time. That is the right shape for "clean air costs you minutes — how many will you spend?"

Nothing downstream of the model is built for this product. The visual language is stock shadcn-on-Tailwind with a green accent hardcoded over an untouched neutral token set: `src/index.css:13` sets `--primary` to near-black while every button hardcodes `bg-green-600`. No `font-family` is declared anywhere, so the type runs on the Tailwind preflight system stack. `--radius` is defined and then ignored in favour of six different rounding classes. `src/App.css` is untouched Vite boilerplate, never imported.

Most damaging: the central number is fabricated. `getMockAirQuality` (`airQuality.ts:126-147`) computes PM2.5 from `Math.sin(lat*100 + lng*100)`. Both upstream sources fail in the shipped app — OpenAQ returns CORS errors on every call, WAQI has no token — so every value a live visitor sees is that sine wave. Strip the green and the leaf icon and this is a generic A-to-B planner with a weather widget.

The README's "Premium UI: Modern dark theme with glassmorphism" describes software that does not exist. `index.css:37-65` defines a full `.dark` palette and `tailwind.config.js` sets `darkMode: ["class"]`, but nothing ever adds that class. The dark theme is unreachable dead code.

**Deterministic scan:** the CLI detector returned 3 findings across `src`, all of rule `border-accent-on-rounded`, at `AirQualityPanel.tsx:52`, `RouteInfo.tsx:28`, `Sidebar.tsx:108`. **All three are false positives** — each is the standard Tailwind spinner idiom (`animate-spin rounded-full border-b-2`), where the partial ring is what makes the spin legible. Net real findings from the source scan: zero.

The built `dist/index.html` scan returned zero findings, but that is structurally uninformative rather than a clean bill of health: the body is exactly `<div id="root"></div>`, so a static engine has no markup to evaluate. Assessment B proved the engine works by injecting a positive control against the same built CSS, which immediately fired a `low-contrast` hit.

**Browser overlay** (injected successfully, then torn down) reported 6 anti-patterns, of which the load-bearing one is real:

- `low-contrast` — **3.2:1 against a 4.5:1 requirement**, near-white on `#16a34a`, on the "Calculate Route" primary button. Measured three independent ways (overlay, hand computation at 3.16:1, CLI positive control at 3.3:1). The instance sampled was the disabled state, which WCAG exempts, but the enabled state uses the identical colour pair, so the primary call to action fails AA.
- `flat-type-hierarchy` — sizes 12/14/16/20/22px, a 1.8:1 ratio across the whole document.
- `nested-cards` — card inside card, twice.
- `ai-color-palette` flagged the logo tile as a "cyan gradient"; the gradient is `from-green-500 to-emerald-600`, so the rule's description misfires here.

**Accessibility evidence** from the live page: 5 buttons with no accessible name (`TopBar.tsx:22`, `TopBar.tsx:64`, `Sidebar.tsx:76`, `App.tsx:145`), and 4 of 4 form inputs with no programmatic label — the visible "From"/"To" text is never associated, leaving the placeholder as the only name source. Heading outline is well formed (h1 → h2 → h3) and there are zero positive tabindex values. The 24 images with empty alt are Leaflet map tiles, which is correct treatment.

## Overall Impression

The skeleton is right and the surface is unbuilt. Someone thought carefully about what a clean-air route planner should *say* — three tradeoffs, a rationale per option, air quality as a peer metric to distance — and then rendered it in library defaults with a green tint. That would be an ordinary polish job.

What makes it urgent is that the product's central number is invented and presented as measurement, complete with clinical advice, to an audience defined in the README as people with asthma and parents with strollers. The biggest opportunity is not visual. It is to make the interface tell the truth about what it knows, and only then make it beautiful.

## What's Working

**The polyline casing** in `Map.tsx:177-193` draws a dark `#111827` stroke 4px wider beneath every route, then the coloured line on top, with unselected routes dashed at 0.45 opacity. That is real cartographic craft: it is what keeps a green route legible over a green park polygon and an amber route legible over an amber trunk road on arbitrary OSM tiles. It is the one visual decision here that could not have been pasted from a component library.

**The bottom-sheet header copy** at `App.tsx:184-189` cycles "Plan your route" → "Ready to calculate" → "3 routes found". A collapsed sheet that tells you where you are in the task, at zero screen cost. It is the best string in the product.

**The three-route framing with a rationale per option.** `getRouteMeta` (`RouteInfo.tsx:46-68`) names the axis each option optimises instead of making the user infer it from numbers. The execution buries these notes in 12px gray, but the model is correct and should survive any redesign.

## Priority Issues

### [P0] Fabricated air-quality data is presented as measurement, with clinical advice attached

**Where:** `airQuality.ts:126-147`, surfaced at `AirQualityPanel.tsx:83-86`, `:119-135`, `:147-153`, and `RouteInfo.tsx:176`, `:187`.

**Why it matters:** Both upstream sources fail for live traffic, so 100% of visitors see `basePM25 = 25 + |sin(lat*100 + lng*100)| * 30`. The UI renders that as "53 µg/m³", tags it "Moderate", and tells the reader that "people with sensitive respiratory systems should limit prolonged outdoor activity". The only disclosures are the word "mock" in a 12px outline badge and an amber "Estimated data" box placed *below* the number the reader has already believed. "Estimated" is also the wrong word: estimation implies a model over real inputs.

**Fix:** Make synthetic data structurally unable to look like measurement. When `source === 'mock'`, render no numeric value at all — a neutral "No air-quality data for this location" state, with pollutant rows, the recommendation and the per-route PM2.5 column suppressed. Separately, fix the transport so the real path is the default path, and surface a visible error instead of `console.debug` when it is not.

**Suggested command:** `/impeccable harden`

### [P0] The clean-air promise is discarded at handoff, and the default selection is the fastest route

**Where:** `share.ts:4-29` (no `waypoints` parameter), `useRoutePlanner.ts:49` and `:77` (`setSelectedRouteIndex(0)` after every calculation and every mode change).

**Why it matters:** These compound. The visitor does the work to find a cleaner path, the app pre-selects "Direct" for them, and then "Open in Google Maps" — the only way to actually navigate, and therefore the real end of the task — sends origin and destination only. Google serves its own default and the person walks the arterial believing they chose the clean route. Switching walk to bicycle also silently resets a deliberately chosen route back to index 0.

**Fix:** Default-select the cleanest route rather than index 0, and say so on the card when the cleanest is also the slowest. Preserve the selection across travel-mode changes by matching on `route.type`. Append downsampled waypoints to the Google Maps URL, or relabel the button to admit that only the endpoints transfer.

**Suggested command:** `/impeccable harden`

### [P1] Every mobile touch target is under 44px and the map is reduced to a 203px strip

**Where:** measured at 375×812 — Calculate Route 231×36, address inputs 305×36, swap button 32×32 (`Sidebar.tsx:80`), header icon buttons 36×36, sheet toggle bar 375×36. Sheet height 536px of 812 (`App.tsx:167-222`, `isMobilePanelOpen` defaults true). Zoom controls removed at `index.css:135-138`.

**Why it matters:** This is a walk-planning app, so the phone is the primary device and the user is often standing or one-handed. No control meets the 44px platform norm, and the 32px swap button misses even the relaxed 24px WCAG 2.2 floor. Meanwhile the panel that instructs "click on the map" covers 66% of the map, and the zoom buttons that would let someone aim that click have been deleted, leaving pinch as the only option.

**Fix:** Raise controls to `h-11` at the mobile breakpoint and give the swap button 44×44. Default the sheet to collapsed so the map gets ~650px. Restore `.leaflet-control-zoom` on mobile above the collapsed sheet. Add a locate-me control.

**Suggested command:** `/impeccable adapt`

### [P1] The severity palette is used as foreground; the primary call to action fails AA

**Where:** `RouteInfo.tsx:175` and `:139-147`, `AirQualityPanel.tsx:83` and `:89-94`; the Calculate Route button in `Sidebar.tsx:100`.

**Why it matters:** The severity ramp `#22c55e / #84cc16 / #eab308 / #f97316 / #ef4444` is a set of saturated mid-tones designed for fills, used as text. `#f97316` on white is about 2.8:1 where 4.5:1 is required. The 30px headline in `#eab308` is about 1.9:1, failing even the 3:1 large-text threshold. White on the `#eab308` badge is about 1.9:1. The detector independently measured the primary button at 3.16:1. Every one of these is the number the product exists to communicate, for an audience that skews older. Colour is also the sole carrier of severity, so the route polylines are undifferentiated for a red-green colour-blind reader.

**Fix:** Split the ramp into a light fill token and a dark text token per band, use the dark token for all text and badge foregrounds, and keep the saturated value for map strokes only. Darken the primary button to clear 4.5:1. Add a non-colour severity cue per band and distinct dash patterns per route.

**Suggested command:** `/impeccable colorize`

### [P1] The route card header collapses under real content

**Where:** `RouteInfo.tsx:124-148`, a single `flex items-center justify-between` holding icon, label, Selected badge, note and level pill.

**Why it matters:** With the real string "Unhealthy for sensitive groups" the pill wraps to three lines and roughly doubles the height of everything beside it. "Green" and "Balanced low pollution" touch with no gap. Below it, `grid-cols-3` wraps "1 h 14 min" and "70.5 µg/m³", so the three cards' metric rows never align and the one comparison the product exists to enable — scanning the PM2.5 column — requires re-finding the number in each card.

**Fix:** Two rows. Label and icon left, level pill right-aligned with a fixed max-width and a short band name. The rationale note gets its own full-width line. Give the metrics grid explicit min-widths so each value holds one line and the columns align across cards. Reconcile the legend band names with the badge band names and add the missing top band.

**Suggested command:** `/impeccable layout`

### [P2] Icon-only controls and address inputs are unreachable by assistive technology

**Where:** `TopBar.tsx:22`, `TopBar.tsx:64`, `Sidebar.tsx:76`, `App.tsx:145`; the From and To inputs in `LocationSearch.tsx`.

**Why it matters:** Five buttons announce as "button" with no name. All four address inputs have no programmatic label, leaving the placeholder as the only name source — and the placeholder truncates on mobile to "Enter address or click on the ma". The autocomplete is not a combobox: no `role`, no `aria-expanded`, no `aria-activedescendant`, and no key handler, so the suggestion list cannot be reached by keyboard at all. Route results arrive with no live region, so a screen-reader user never learns the calculation finished.

**Fix:** Add `aria-label` to every icon-only control, associate each input with its visible label, implement the combobox pattern with arrow and Enter handling, and announce route results in a polite live region.

**Suggested command:** `/impeccable audit`

### [P2] Silent dead map click once both points are set

**Where:** `useRoutePlanner.ts:101-133`.

**Why it matters:** The app teaches that tapping the map sets a point, then stops responding with no toast, no cursor change and no hint. Markers are not draggable (`Map.tsx:124`, `:151`). The only escape is Clear, which wipes both points and all routes.

**Fix:** Make markers draggable and recalculate on drag end. On a click with both points set, offer a small anchored menu or at minimum a toast explaining how to move a point.

**Suggested command:** `/impeccable clarify`

## Persona Red Flags

**Asthma sufferer checking before a 20-minute walk to the clinic.** She gets three cards all stamped orange "Unhealthy for sensitive groups" at 70.5 / 71.1 / 69.3. The app pre-selects Direct — the one it measured as more polluted than the route it named Green — and nothing acknowledges that the green route lost. Every card carries "AQ source: mock", and the panel pairs a confident 53 with an instruction to limit outdoor activity, generated from a sine function. There is no "conditions are bad everywhere right now", no time-of-day suggestion, no mask prompt. She taps Open in Google Maps and gets the arterial, because `share.ts:11-15` sends no waypoints.

**Parent with a stroller, one hand free, standing on the pavement.** The bottom sheet is open by default over 536 of 812px, so the map she is told to click is a 203px strip, and the zoom buttons were deleted, so aiming requires the hand that is on the stroller. She tries to drag the pill handle at `App.tsx:171`; it is decorative, and only the 36px chevron bar toggles. Calculate Route is 36px tall, the swap button 32×32. There is no locate-me control, so she types her own address one-handed while the map sits over Moscow. The one line written for her — "Great choice for allergy sufferers and children!" at `RouteInfo.tsx:195` — only renders when safety is `safe`, which none of these routes were.

**Keyboard-only and screen-reader user.** The address autocomplete has zero elements with `role=combobox` and binds no key handler, so the suggestion list is visually present and functionally unreachable. The Walk/Bicycle control has zero `role=tab` and announces as two unrelated buttons with no selected state. Five icon-only controls announce as "button". The only live region on the page is the toaster, so route results are never announced. The sidebar collapse toggle is 20th in tab order, after "Open in Apple Maps".

## Minor Observations

- `src/App.css` is untouched Vite boilerplate, never imported. Delete it before someone imports it and centres the app.
- `reverseGeocode` sends no `accept-language`, so map-click addresses come back in the local language under an English UI.
- On mobile the Sonner toast renders under the `z-[500]` header and is clipped, so the key guidance string is occluded by branding.
- `PlannerSidebar` mounts twice at all times; the mobile copy is `display:none`, not unmounted, so every point selection fires the air-quality chain twice and burns free-tier quota.
- `Map.tsx:92` uses `setView` and never `fitBounds`, so a route longer than one screen at zoom 13 extends off-canvas with no indication.
- The Air Quality panel is fed `startPoint || endPoint` and never says which end of the journey the number describes.
- `buildShareText` heads the clipboard payload "🌿 Green Path Route", a third name after "Safe Path" in the h1 and `green-path` in the repo.
- Route cards use `key={index}` and no `aria-pressed`, so selection is conveyed by border colour alone.
- Air-quality overlay circles are fixed at 200m radius, one per sample point, so dense sampling compounds the fills and implies worse air where there is only more sampling.

## Questions to Consider

1. If the air-quality data is fabricated on every live request, what is the honest version of this product today? A route planner that *would* use air quality, shipped with the feature visibly switched off, would be less impressive and more trustworthy.
2. The app is named Safe Path and its audience is people whose lungs are at stake. Why does it default-select the fastest route?
3. When all three routes come back unhealthy — the case that matters most — the app has nothing to say. What is the screen that says "don't go now, go at 7pm"? Is the real product a timing advisor rather than a router?
4. The last thing a visitor does is leave for Google Maps, which discards everything computed here. If the handoff cannot carry waypoints, is the honest move to build turn-by-turn, or to stop calling this a routing app?
5. You show "Health score: 44/100" with no scale. If you deleted that badge tomorrow, would anyone notice, and what else on the card exists because it was easy to compute rather than because someone needs it?
